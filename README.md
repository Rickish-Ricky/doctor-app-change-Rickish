# Doctor Appointment App

Учебный проект: мобильное приложение для записи к врачу.

## Текущее состояние
- завершено 40% работ;
- использовано 45% бюджета;
- velocity: 18 SP за итерацию;
- осталось 54 SP в бэклоге;
- сейчас конец 3-й итерации из 6.

## Новое требование
Заказчик просит добавить видеоконсультации. Решение ещё не принято.
## Решение по видеоконсультациям

**Вопрос заказчику:** Видеозвонок должен быть встроен в приложение
или достаточно перехода во внешний сервис? От ответа зависит объём работы.

**Категория MoSCoW:** Should

**Влияние на сроки:** 54 SP ≈ 3 итерации при velocity 18 SP/итерацию,
а осталось тоже 3 итерации. Новое требование сдвигает финиш или требует
вытеснения других задач из бэклога.

**Влияние на бюджет:** Дополнительная разработка + возможный сторонний
сервис (видео SDK/серверы/лицензии) → рост стоимости. При фиксированном
бюджете — сокращение объёма других функций.

**Решение:** упростить (переход во внешний сервис) и уточнить объём
у заказчика до включения в план.

**Почему:** требование важно, но не блокирует MVP (запись к врачу уже
работает). Слова «критически важно» не делают функцию Must без оценки
ценности и реальности сроков. Категория Should выбрана, потому что объём
не уточнён, а бэклог уже заполняет оставшееся время.
